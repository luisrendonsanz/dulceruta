# Migración de DulceRuta a Cloudflare D1

Esta rama es de preparación. **No se debe fusionar en main hasta crear D1, instalar el esquema y configurar la contraseña secreta.** La web pública sigue trabajando con JSON mientras tanto.

## Paso A — Crear la base de datos

1. En Cloudflare abre **Storage & databases → D1** (en algunas interfaces, **Workers & Pages → D1**).
2. Crea una base nueva llamada `dulceruta-db`.
3. Abre su sección **Console** y ejecuta las sentencias del archivo `schema.sql`. Esto crea las tablas `puntos` y `meta` y comienza en 0 lugares.

## Paso B — Conectar D1 con Cloudflare Pages

1. Abre **Workers & Pages → dulceruta → Settings → Bindings**.
2. Pulsa **Add binding → D1 database**.
3. **Variable name:** `DB` (exactamente mayúsculas). Base de datos: `dulceruta-db`.
4. Confirma que el binding sea para el entorno **Production**. Para previsualizaciones, configura también Preview si vas a probar esta rama allí.
5. Ve a **Settings → Variables and Secrets** y crea el secreto de servidor `ADMIN_PASSWORD` para Production. Elige una nueva contraseña única de **16 caracteres o más**, guárdala en tu gestor de contraseñas y **no la envíes al chat ni la subas a GitHub**. La contraseña JavaScript antigua no debe reutilizarse.
6. Guarda. En Cloudflare Pages, los cambios de bindings y secretos requieren volver a desplegar para aplicarse.

## Paso C — Activar el código

Después de confirmar los pasos A y B, fusiona `feature/cloudflare-d1` en `main` y comprueba que Cloudflare Pages construya correctamente la aplicación.

## Paso D — Prueba

- Abre `https://dulceruta.pages.dev/api/puntos`. Debe devolver `[]`.
- Abre `/editor.html`. Accede con la nueva contraseña de Cloudflare (no la antigua).
- Registra una casa de prueba desde `/registro.html`; descarga su JSON como antes.
- En el administrador importa el JSON, apruébalo y pulsa **Publicar cambios en el mapa**.
- Comprueba que se vea en la página principal sin modificar ningún archivo en GitHub.
- Elimínala del borrador, pulsa **Publicar cambios en el mapa** y verifica que el mapa vuelva a quedar vacío.

## Comportamiento importante

- Registrar un lugar **no lo publica automáticamente**; requiere aprobación.
- El borrador del administrador permanece en el dispositivo (localStorage); haz respaldos si manejas muchas casas.
- El botón **Publicar cambios** reemplaza todos los lugares públicos por la lista completa del borrador y aumenta una revisión del servidor para detectar conflictos entre sesiones.
- D1 no recibe nombres ni apellidos de los solicitantes; se guardan exclusivamente los siete campos públicos.
- El mapa recarga D1 por red y puede recurrir a `puntos.json` si la API está caída. Evita utilizar un JSON viejo como fuente oficial tras activar D1.
- Cloudflare Pages del antiguo dominio GitHub Pages no cuenta con esta API; es conveniente desactivar la publicación anterior cuando confirmes todo.
- El secreto `ADMIN_PASSWORD` se verifica en el servidor y una sesión firmada se almacena en una cookie HttpOnly válida 8 horas.
- Para defender ataques de fuerza bruta, añade una regla Cloudflare WAF/rate limiting al endpoint `/api/admin/login`, o usa Cloudflare Access.
